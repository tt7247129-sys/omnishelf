# omnishelf.cc 网站执行方案 v1

> 角色:网站项目主导(方案由我拍板、我执行;你需要做账号/浏览器/审稿类动作)。
> 一句话定位:**一个能立刻下到书、也教你怎么读的官方站**——下载是唯一主 CTA,书库是流量入口,阅读知识是信任来源。

## 0. 我拍板的四个决定

| # | 决定 | 理由 |
|---|---|---|
| D1 | **一个站,三个功能区,一个主按钮**:`/` 承接下载,`/books/` 书库,`/reading/` 阅读知识;全站只有一种主按钮「免费下载」 | 承接站的最大杀手是"什么都想放";标杆站(Standard Ebooks/Gutenberg)都是"每页一个动作" |
| D2 | 书库**只做公版书 + 免费原创 + 正版付费导流**,绝不做盗版镜像 | 版权是唯一能让站和 App 一起死的风险;也别碰 LibGen/Z-Library 类站点 |
| D3 | 技术栈 **Astro + Cloudflare Pages + Pagefind**,纯静态、免登录、无 Cookie 追踪 | 书页要能被搜索引擎收录(静态最佳);维护成本≈0,不烧服务器 |
| D4 | 语言 **中文优先、英文同步建模板**(zh 上线,en 骨架同批) | 你的用户盘在国内;但 .cc 域名与英文书库天然能接海外自然流量 |

**北极星指标**:自然搜索 → 站内「下载」点击 → **Play 商店实际安装**(用 Play Install Referrer 归因,不依赖广告 ID)。

## 1. 研究:10 个承接/转化做得最好的站

数据为 2026 年公开估算,用于判断体量与打法,不作为精确财务依据。

| # | 站点 | 体量(月访问) | 它的承接打法 | 我们可偷的点 |
|---|---|---|---|---|
| 1 | [Project Gutenberg](https://www.gutenberg.org) | ~10.5M | 6 万+ 公版书,每本书一个极简页 + 直链下载;靠海量书页吃长尾搜索 | **程序化书页 = SEO 引擎**;下载路径不超过两次点击 |
| 2 | [Open Library](https://openlibrary.org) | ~8.3M | 借阅模型(14 天),书架与愿读清单;注册后留存 | 「想读/在读/读完」轻量状态,提升回访 |
| 3 | [Goodreads](https://www.goodreads.com) | ~110M | 书评社区 + 榜单 + 年度挑战 | 榜单页(如「一生必读 100 本」)是稳定流量入口 |
| 4 | [Wattpad](https://www.wattpad.com) | ~90M | UGC 连载;读完一章就催下载 App | 「先读一章(网页)→ 继续读请用 App」的**内容前置漏斗** |
| 5 | [BookBub](https://www.bookbub.com) | 大(未取数) | 邮件推送免费/低价书,落地页一键跳各商店 | 邮件/推送做回访,落地页做分发 |
| 6 | [Standard Ebooks](https://standardebooks.org) | ~350K | 只做 900+ 本,但**排版质量**极高;每本书页即作品页 | 少而精:书页质量本身就是品牌 |
| 7 | [ManyBooks](https://manybooks.net) | ~0.8–1.3M | 免费书 + 付费区 + 联盟导流;分类筛选做得极细 | **免费/付费分层**与筛选器,是最像我们目标的模板 |
| 8 | [Readwise](https://readwise.io) | ~680K | 博客讲"怎么读/怎么记",内容养出高意向用户再转化订阅 | **知识内容 → 产品转化**的原型,我们可照搬结构 |
| 9 | [F-Droid](https://f-droid.org) | 中量 | 开源应用分发,页面极简、可信度靠"开源"背书 | 用"开源/无广告/无追踪"做信任状与对比表 |
| 10 | [Blinkist](https://www.blinkist.com) | 大量 | 落地页先说"能带给你什么",再给 15 分钟摘要 | 首屏一句话价值主张(100 像素内说清) |

## 2. 推荐借鉴的 3 个站(以及抄什么、不抄什么)

### ① Standard Ebooks —— 抄「书页质量」和「少而精」
- **抄**:每本书独立页(封面/作者/简介/下载按钮/相关书),排版干净;只收录精校公版书,用质量建立信任。
- **不抄**:它不做 App,也没有商业转化;我们要在书页底部补一条「用 OmniShelf 读它更好」的软转化。
- 落到我们:**书页 = 最小的产品页**。

### ② ManyBooks —— 抄「免费/付费分层」与「筛选」
- **抄**:免费区与特价/付费区明确分开;左侧多维筛选(格式/语言/题材/长度);付费书走联盟链接。
- **不抄**:它广告与联盟位偏重,会稀释品牌;我们只保留一处克制的「正版购买」入口。
- 落到我们:**`/books/free/` 与 `/books/paid/` 两条路径**,付费只做导流不托管文件。

### ③ Readwise —— 抄「知识内容养高意向用户 → 转化产品」
- **抄**:把「怎么读、怎么记、怎么用」写成体系化专栏;文章内嵌产品能力演示;结尾一个 CTA。
- **不抄**:它面向订阅 SaaS,写作偏英文长文;我们要做中文可读的短篇 + 图示。
- 落到我们:**`/reading/` 12 篇支柱 + 36 篇支撑**,每篇结尾接「下载 App」。

> 备选第 4 个:Project Gutenberg 的**程序化书页 SEO**(我们用它做流量底盘)。

## 4. 下载承接与转化设计(核心)

- **唯一转化路径**:任意页面 CTA → `/go/play?src=<页面ID>` → Play 商店。
- **Android 归因**:使用官方 [Play Install Referrer API](https://developer.android.com/google/play/installreferrer),把 `utm_source=omnishelf.cc&utm_medium=web&utm_campaign=<位置>` 透传;App 首次启动上报(无需广告 ID,符合我们"无追踪"承诺)。
- **桌面端**:CTA 同时给二维码(扫码直达 Play),二维码下方写「扫码安装 OmniShelf」。
- **移动端**:底部悬浮条常驻「免费下载」,滚动 300px 后出现。
- **书页软转化**:「下载 EPUB」与「用 OmniShelf 打开」并列;后者走 `intent://` 深链,未安装则回落 Play。
- **文章软转化**:结尾一句「这本书用 OmniShelf 读,能做笔记、能听书」+ 一个按钮。
- **A/B(第 4 周)**:按钮文案「免费下载」vs「免费下载(无广告)」;首屏截图 3 张 vs 1 大图。

## 5. 书库方案(第二作用的落地)

### 版权红线(必须先定)
- ✅ 允许:**公版书**(中国:作者卒年 ≤ 1975;美国/欧盟:以 Gutenberg/Standard Ebooks 标注为准)、**自有原创**、**明确授权**的免费书。
- ✅ 付费:**只做联盟导流**(Amazon / Kobo / Apple Books / 得到/微信读书等),**不托管受版权保护的文件**。
- ❌ 禁止:任何盗版源、网盘转载、LibGen/Z-Library 类内容。
- 每本书页固定显示来源与版权状态;`/dmca` 提供下架通道(hello@omnishelf.cc)。

### 数据模型(每本书)
`slug, 标题, 作者, 译者, 语言, 题材, 字数/页数, 版权状态(free-public-domain / free-original / paid-affiliate), 封面, 简介 120 字, 下载格式(EPUB/PDF), 下载链接, 正版购买链接(可选), 相关书 3 本, 结构化数据`.

### 首批 300 本(第 2 周交付 100 本)
- 中文公版 60:四大名著、儒林外史、聊斋、唐诗宋词、四书五经、鲁迅(卒 1936)、朱自清(1948)、老舍(1966)等。
- 英文公版 200:Gutenberg/Standard Ebooks 精选(小说/哲学/科幻/儿童)。
- 免费原创 20:OmniShelf 官方精选书单/导读手册(自有版权)。
- 付费导流 20:现代畅销书(只放封面+简介+购买链接,不提供文件)。

### 导入流水线
`CSV/Markdown 元数据 → 脚本抓封面并压缩 → 生成 Astro Content Collection → 构建时校验(必填字段/版权状态/坏链) → 自动生成 sitemap + JSON-LD`。

## 7. 技术方案

| 项 | 选择 | 说明 |
|---|---|---|
| 框架 | Astro 5(Content Collections) | 静态输出,书页/文章页天然 SEO 友好 |
| 样式 | Tailwind 4 + 设计令牌 | 直接复用 App 调色板(朱砂 #8E2B21、纸 #FBF8F2、墨 #241815)与宋体 |
| 部署 | Cloudflare Pages | 免费、全球 CDN、支持 .cc 域名与自定义 headers |
| 搜索 | Pagefind | 纯静态全文搜索,构建期生成,零服务 |
| 分析 | Umami(自托管)或 Cloudflare Web Analytics | 无 Cookie、合规、能看到 CTA 点击 |
| 图片 | AVIF/WebP + 显式尺寸 | 封面统一 600×900,避免 CLS |
| 性能预算 | LCP < 1.5s、JS < 50KB | 书页几乎零 JS |
| i18n | Astro 原生路由 `/zh/` `/en/` + hreflang | 首期 zh 上线,en 同批骨架 |

SEO 关键词矩阵(中文优先):
- 下载类:免费电子书阅读器、epub 阅读器 安卓、无广告阅读器、支持 mobi 的阅读器
- 书库类:免费 epub 下载、公版书 下载、古典名著 epub、英文原版书 免费
- 知识类:如何阅读一本书、读书笔记 方法、SQ3R、主题阅读、读完就忘

结构化数据:书页 `Book` + `offers`;文章 `Article`+`FAQPage`;首页 `SoftwareApplication`(含 Play 链接)。

## 10. 风险与红线

| 风险 | 应对 |
|---|---|
| 版权投诉(最高) | 只做公版/原创;付费只导流;`/dmca` + 24h 响应;来源标注 |
| Google 对"下载站"的信任评级 | 不放弹窗/诱导下载/捆绑;HTTPS、清晰的所有者信息、无恶意跳转 |
| .cc 域名信任度 | 用 About/开源/Play 官方链接建立可信度;申请 GSC/Bing |
| 内容维护成本 | 静态站 + 内容集合;每月只更 4 篇 + 20 本书 |
| 与 App 品牌不一致 | 设计令牌与文案直接从 App 取;不出现广告/联盟堆砌 |

## 11. 需要你配合的 6 件事(按顺序)

1. **确认 Play 正式链接**(包名 `cc.omnishelf.reader`)与是否已有商店页。
2. **Cloudflare 账号 + omnishelf.cc 的 DNS 权限**(或由你代操作解析)。
3. **Google Search Console / Bing 站长验证**(浏览器里点两下,我把文件给你)。
4. **确认语言顺序**:我建议 zh 先上线、en 同批骨架(你可否决)。
5. **确认版权口径**:公版 + 免费原创 + 正版付费导流(不托管付费文件)。
6. **确认联盟链接是否接受**(Amazon/Kobo 等);若否,付费区改为"去商店搜索"按钮。
7. 确认 DMCA 联系邮箱(`hello@omnishelf.cc` 是否可用)。
