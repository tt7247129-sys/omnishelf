# 语言与地区:现状与方案

## 一、机制已经是对的

应用有三层语言逻辑,全部现成:

1. **默认跟随系统语言** — `AppState.appLang = MY_SYSTEM_LANG`
2. **可手动覆盖** — 设置里有语言选择(`AppLang` 对话框)
3. **未覆盖语言自动回退英文** — `values/` 是默认资源集,Android 按 locale 匹配失败即用它

**实测验证**:把模拟器系统语言设为 `de-DE` 并重启,应用界面自动变为德语
(`VERLAUF / Bibliothek / Ordner / Favorit`),见 `docs/ui-shots/verified/07-german-locale.png`。
不需要任何代码改动。

## 二、覆盖度盘点

当前随包发布 **42 个语言**:

```
ar be bg ca cs de el es eu fa fi fr ga gl he hi hu id it iw ja kk ko
lt ml nl no pl pt ro ru sc sk sv sw ta th tr uk vi zh-rCN zh-rTW
```

对照全球使用人数前 50 的语言,**缺口约 12 个**:

| 语言 | 代码 | 说明 |
|---|---|---|
| 孟加拉语 | bn | 2.3 亿母语者 |
| 乌尔都语 | ur | 2.3 亿 |
| 泰卢固语 | te | 9500 万 |
| 马拉地语 | mr | 8700 万 |
| 旁遮普语 | pa | 8000 万 |
| 古吉拉特语 | gu | 5700 万 |
| 卡纳达语 | kn | 4500 万 |
| 缅甸语 | my | 3300 万 |
| 马来语 | ms | 3300 万 |
| 菲律宾语 | fil | 2800 万 |
| 乌兹别克语 | uz | 2700 万 |
| 尼泊尔语 | ne | 1900 万 |

这些地区的用户**现在看到的是英文**——符合"未覆盖默认英语"的要求,但不是最优体验。

## 三、为什么不能一键补上

项目有一条硬规则:**新增任何字符串必须同步到全部语言文件,行数必须与英文一致**
(`Builder/build-librera-beta.sh` 会在行数不一致时直接失败)。

所以"新增一个语言"不是加一个目录,而是**完整翻译约 724 条字符串**。12 个语言 = 8700 条。
机器翻译能填满,但会把"翻页模式"译成奇怪的东西,出现在设置页里——比英文回退更糟。

## 四、建议的推进方式

1. **先补最有价值的 4 个**:孟加拉语、乌尔都语、马来语、菲律宾语
   (前两个是人口大国,后两个是东南亚主要市场)
2. 每个语言由我逐条翻译,而不是机翻直出,重点检查:设置项名称、按钮文案、错误提示
3. 每补一个语言,用 `setprop persist.sys.locale <code>` 在模拟器上实测一遍界面
4. 全部 12 个补完约需 4–6 轮(每轮 2–3 个语言 + 实测)

## 五、一个取舍要说明

补齐语言**不会提升现有 42 个语言用户的体验**,只影响新增地区的可用性。
如果优先目标是"让现有用户觉得好用",语言应该排在划词菜单、听书面板、设置分组之后。

我的建议顺序:先做完 UX 五项,再补语言包。
