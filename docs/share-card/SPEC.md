# 书摘分享卡 · 设计与技术方案(1.2.0)

## 一、为什么做这个

阅读类 App 唯一被验证过的自然增长循环是**分享书摘**:
用户读到好句子 → 生成一张好看的卡片 → 发到微信/微博/Reddit → 卡片带品牌与短链 → 有人来装。

成本为零,且每次分享都是一次免费曝光。这是 1.2.0 的主打功能。

## 二、用户流程(3 步)

```
阅读时长按选中文字
   ↓ 选中面板已有「分享」位置(现在折叠在 ⋮ 里,改到第一层)
点「分享书摘」→ 预览卡片(可左右切换 3 套模板)
   ↓ 点「分享」
系统分享面板(微信/微博/小红书/Reddit/保存图片)
```

## 三、卡片规格

| 项 | 值 |
|---|---|
| 尺寸 | 1080 × 1440(3:4,微信/微博/小红书通用) |
| 内容 | 引文(最多 120 字)、书名、作者、页码(可选)、品牌行 |
| 品牌行 | `OmniShelf · omnishelf.cc` |
| 字体 | 系统字体;中文用 Noto Sans SC / 思源黑体,英文用 Roboto |
| 深色/浅色 | 按当前阅读主题自动选,用户可切换 |
| 水印 | 右下角小字,不遮挡引文 |

模板(3 套,已出样张):
1. `card-1-cinnabar` 朱砂:品牌色满版,节日感强
2. `card-2-paper` 象牙纸:留白多,适合长引文
3. `card-3-night` 夜间:深色,夜间阅读时默认选中

## 四、技术方案

| 步骤 | 实现 |
|---|---|
| 生成 | `Canvas` + `StaticLayout` 绘制到 `Bitmap`(1080×1440,ARGB_8888) |
| 输出 | 写入 `cacheDir/share-cards/q_<timestamp>.png` |
| 分享 | `FileProvider` + `ACTION_SEND`(type `image/png`),同时提供 `EXTRA_TEXT` 文案 |
| 权限 | 无需新权限(cacheDir + FileProvider) |
| 性能 | 生成耗时目标 < 120ms,后台线程 + 预览占位 |
| 兜底 | 字体缺失时降级系统默认字体;超长引文截断并加省略号 |

## 五、归因与统计(零成本)

- 卡片品牌行固定写 `omnishelf.cc`
- 落地页 `https://omnishelf.cc/share/`(静态页,说明 App 是什么 + 下载链接)
- 短链带参数:`omnishelf.cc/share/?from=card` → 站点统计(Umami/Plausible 自建)能看出分享带量
- Play 侧:安装来源只能看商店概览,不做过度归因(避免隐私问题)

## 七、风险与对策

| 风险 | 对策 |
|---|---|
| 中文字体渲染成方框 | 打包思源黑体子集,或用系统字体 + 检测回退 |
| 长引文排版溢出 | 字号自适应:>80 字逐级降字号,>120 字截断 |
| 微信不接受 `image/png` | 同时提供 `image/jpeg` 兜底 |
| 用户误以为要授权 | 分享面板前不弹任何权限请求 |
| Play 政策 | 分享卡属正常功能,无激励、无刷评风险 |

## 八、上线后怎么衡量

| 指标 | 目标(上线 30 天) |
|---|---|
| 分享卡生成次数 | ≥ 200 |
| 分享出去的比例 | ≥ 40% |
| `omnishelf.cc/share/` 访问 | ≥ 100 |
| 从落地页点到 Play | ≥ 30 |
