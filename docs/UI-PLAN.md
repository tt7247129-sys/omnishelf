# OmniShelf UI 优化方案(调研 → 评估 → 决策)

> 状态:**方案待决策,未改任何代码。**
> 依据:真机实拍(Android 13 模拟器,1080×1920)、源码结构、国内头部阅读器公开更新说明。

---

## 一、调研方法与样本

### 1.1 样本选择

按应用商店图书类排名与用户规模,取五个参照对象:

| 应用 | 参照价值 |
|---|---|
| 微信读书 | 排版与沉浸阅读的行业基准;2026 年 4 月的更新集中解决"书架管理 + 沉浸阅读" |
| 掌阅 iReader | 排版参数最细,主题/翻页动效体系完整 |
| 番茄小说 | 阅读页极简、翻页动效与听书入口的典型 |
| QQ 阅读 | 书城与阅读页的分层信息架构 |
| 咪咕阅读 | 运营商体系下的稳定版式与听书 |

### 1.2 方法说明(重要)

我没有在本机安装这五个应用做逐帧对比——它们需要登录、有版权内容、且部分不提供本地书导入。本方案对它们的判断来自两类可核验材料:

1. **公开更新说明**:例如微信读书鸿蒙版 2026-04 的更新明确列出「书籍置顶、书架分组、私密阅读、统一笔记、仿真翻页、隐藏他人想法、常驻时间电量、左侧点击翻页」([极客公园报道](https://w.geekpark.net/news/362641))。
2. **长期可观察的交互模式**:打开即读、继续阅读置顶、阅读页双栏工具条、点击分区翻页等。

因此下文把它们的做法归纳为**可迁移的原则**,而不是"照着某个截图抄"。任何需要精确还原的视觉细节,在执行阶段都要重新核对真机。

### 1.3 从五个样本提炼的 8 条原则

| # | 原则 | 具体表现 |
|---|---|---|
| P1 | 打开即读 | 启动后直接进入上次阅读位置,不经过首页 |
| P2 | 继续阅读优先 | 书架第一屏是"最近在读",而不是全部藏书 |
| P3 | 信息密度分层 | 阅读页极简 → 书架中等 → 详情页丰富 |
| P4 | 手势优先,按钮兜底 | 左右点按翻页、中间呼出菜单,工具栏是备选 |
| P5 | 排版是功能不是设置 | 默认值就要能读,设置项只做微调 |
| P6 | 沉浸 = 色彩连续 | 状态栏、导航栏与纸面同色;阅读时显示时间电量 |
| P7 | 进度可视化 | 封面角标、进度条、剩余时间,至少两种 |
| P8 | 个性化但克制 | 少量高质量主题,不做无限换肤 |

**这 8 条里,OmniShelf 目前满足 P1(部分)、P5(部分),其余基本不满足。**

## 二、现状实测

### 2.1 实拍证据

- 书架:2 列卡片,靛蓝顶栏 + 白色卡片 + 靛蓝底栏
- 阅读页(菜单展开):靛蓝顶栏 + 纸纹底 + 靛蓝底栏,工具栏 14 个图标
- 设置弹窗:青绿色(teal)强调色

### 2.2 问题清单(按严重度)

| 编号 | 问题 | 证据 | 严重度 |
|---|---|---|---|
| S1 | **两套强调色**:顶栏/底栏靛蓝 `#3F51B5` 系,作者名与弹窗按钮青绿 | 书架截图 vs Library Folders 弹窗 | 高 |
| S2 | **底部导航 5 项且标签截断**:"Bookmar…" | 书架截图 | 高 |
| S3 | **卡片结构断裂**:封面在白卡片内,书名/作者/格式溢到卡片外,与下一行无分隔 | 书架截图,第二行标题被裁 | 高 |
| S4 | **底部栏遮挡内容**,无 scrim、无底部内边距 | "Alice's Adventures in Wond…" 被压住 | 高 |
| S5 | **无阅读进度、无继续阅读入口**:卡片上没有百分比,首屏没有"在读"区块 | 书架截图 | 高 |
| S6 | **阅读页 14 个无标签图标**,分两行,语义靠猜 | 阅读页截图 | 高 |
| S7 | **排版默认值失守**:沿用出版商 CSS,标题巨大、自动断词、两端对齐出现大空隙 | "Adven-/tures"、"The Project Gutenberg" 超大标题 | 高 |
| S8 | **状态栏与页面冲突**:靛蓝状态栏压在米色纸面上 | 阅读页截图 | 中 |
| S9 | **正文被底栏裁切**,最后一行只露出半截 | 阅读页底部 | 中 |
| S10 | **术语无解释**:"Paged"、页码 "2 / 259" 与"页"的关系不清 | 阅读页底栏 | 中 |
| S11 | **搜索框与标题合一**:顶部胶囊既是标题又是搜索入口,双击才明白 | 书架顶部 | 中 |
| S12 | **图标风格混用**:实心/描边、线宽不一 | 顶栏三个图标 vs 底栏五个图标 | 低 |
| S13 | **空态无引导**:0 本书时整屏空白,只有一行工具栏 | 首次启动截图 | 中 |

### 2.3 代码层面的约束(决定改造成本)

| 项 | 数量 | 含义 |
|---|---|---|
| 布局文件 | 112 个 | 大改需要逐个回归 |
| 引用 `@color/` 的布局 | 61 个 | 改色板能覆盖一半以上 |
| Java 里 `Color.parseColor` | 74 处 | 硬编码色,需逐一替换为 token |
| Java 里 `setTextColor`/`setBackgroundColor` | 195 处 | 主题化必须走统一入口,否则改不干净 |

**结论:配色统一是可以做的,但必须做成"设计令牌 + 一次性替换",不能靠零散改。**

## 四、优化方案

分四层,每层独立可交付、可回滚。

### T0 — 设计令牌与主题统一(基础层)

**目标**:全站一套色,消除 S1/S8/S12。

1. 定义 `colors.xml` 中的语义令牌:`surface`、`surfaceRaised`、`onSurface`、`onSurfaceMuted`、`divider`、`accent`、`accentOn`。
2. 选定主色。三个候选:
   - **墨绿 `#4A5D4E`**(与网站一致,纸感,低饱和)
   - 靛蓝 `#3F51B5`(维持现状,辨识度高但通用)
   - 暖褐 `#8B6F4E`(纸感更强,深色模式难配)
3. 用脚本把 74 处 `Color.parseColor` 收敛到常量类;61 个布局的 `@color/` 指到新令牌。
4. 阅读页状态栏跟随页面背景色(P6),深色模式同步。

**改动点**:`res/values/colors.xml`、`styles.xml`、`AdsConfig` 之外的颜色常量类、`MainTabs2` 的状态栏控制。
**工作量**:1.5–2 人日。**风险**:中(全局色变,需全屏回归截图)。**回滚**:单 commit 回退。

### T1 — 书架重构(用户第一眼)

**目标**:解决 S2/S3/S4/S5/S13,把书架从"文件浏览器"变成"书架"。

1. **继续阅读区**:顶部一块横向卡片,显示最近 3 本的封面 + 进度 + "继续阅读"按钮,点击直达阅读位置。
2. **卡片重做**:封面圆角、统一 3:4 比例、右下角进度环或百分条、书名 2 行截断、作者一行弱化色、格式/大小移到长按菜单。
3. **底部栏合并**:5 项 → 3 项(书架 / 最近 / 收藏),把"文件夹"移进抽屉,"书签"移进阅读页。标签不再截断。
4. **空态引导**:0 本书时显示"扫描本地图书 / 添加文件夹"两个动作 + 一句说明,而不是空白。
5. **底部安全区**:列表加 `paddingBottom = 底栏高度 + 8dp`,消除遮挡。

**改动点**:`MainTabs2`、`BrowseFragment2`、`browse_item_grid.xml`、`browse_item_list.xml`、`TabsFragment`。
**工作量**:4–5 人日。**风险**:中高(主界面重构)。**回滚**:保留旧布局,用开关切换。

### T2 — 阅读页收敛(核心竞争力)

**目标**:解决 S6/S7/S9/S10,把 14 个图标压到 8 个以内,并修好默认排版。

1. **工具栏收敛**:
   - 顶部保留:返回、目录、字号/排版、更多(把夜间/主题/朗读收进"更多")
   - 底部保留:进度条、上一页/下一页、"朗读"、书签
   - 图标全部带文字标签或长按 tooltip
2. **默认排版**:首次打开覆盖出版商 CSS 的标题字号上限(如 `h1 ≤ 1.6em`),关闭自动连字符(除非用户开启),两端对齐默认关。
3. **状态栏沉浸**:阅读页 `WindowInsets` 全屏,页面背景延伸到状态栏,显示时间与电量(P6)。
4. **底部不裁切**:正文容器底部预留工具栏高度,最后一行完整可见。
5. **术语清理**:"Paged" 改为"翻页",页码区改为"第 2 / 259 页"。

**改动点**:`DocumentActivity`、`read_menu` 相关布局、`BookCSS`、`Config` 默认值。
**工作量**:4–6 人日。**风险**:高(阅读页是所有功能交汇处)。**回滚**:逐项开关。

### T3 — 可选增强(提升"像不像头部产品")

按性价比排序:

| 功能 | 参照 | 工作量 | 风险 |
|---|---|---|---|
| 仿真翻页动效 | 微信读书/掌阅 | 3–4 人日 | 中(低端机掉帧) |
| 阅读进度环 + 剩余时间 | 微信读书 | 1 人日 | 低 |
| 阅读页"常驻时间电量" | 微信读书 | 0.5 人日 | 低 |
| 主题预设(纸/夜/护眼) | 掌阅(克制版) | 2 人日 | 低 |
| 书架分组与置顶 | 微信读书 | 2–3 人日 | 中 |

## 五、明确不做

- ❌ 书城、推荐流、社交动态(与"无广告无账号"冲突)
- ❌ 任何形式的付费墙或会员入口
- ❌ 无限换肤(只做 3 套预设)
- ❌ 云端同步(需要账号)

## 六、决策清单

请从中选**一个套餐**,或逐条勾选:

### 套餐 A:止血版(约 2 人日)
T0 全部。只统一配色与沉浸状态栏。**见效最快,不改变结构。**

### 套餐 B:书架优先(约 6–7 人日)
T0 + T1。用户第一眼看到的界面完成换代。

### 套餐 C:阅读体验优先(约 7–8 人日)
T0 + T2。修好"打开一本书之后"的全部体验。

### 套餐 D:完整体(约 12–14 人日)
T0 + T1 + T2,不含 T3。

### 套餐 E:完整 + 增强(约 18–20 人日)
D + T3 中"仿真翻页 + 进度环 + 常驻时间电量"。

## 七、验收标准(无论选哪个套餐)

1. **视觉**:全应用只有一个强调色;截图对比改造前后;状态栏与页面同色。
2. **可用性**:底部栏不遮挡任何内容;所有图标有可理解标签;空态有动作。
3. **排版**:默认打开 EPUB,标题不超过正文 1.6 倍,无自动断词(除用户开启),最后一行完整可见。
4. **性能**:首屏冷启动不退化超过 15%;翻页帧率不低于 55fps(中端机)。
5. **回归**:112 个布局中,被改动的逐个截图核对;阅读、朗读、书签、注释、OPDS 五条主路径不回归。

---

## 八、建议

如果只能做一件事:**先做 T0**。当前最刺眼的问题不是功能缺失,而是"两个品牌色同时出现 + 阅读页配色断裂",这让人一眼觉得应用没做完。T0 成本最低、观感提升最大。

如果预算允许到一周:**T0 + T1**。书架是用户判断"这应用做没做完"的第一屏,而现在的卡片结构(文字溢出卡片、底栏压字、无进度)是硬伤。

T2 的排版默认值是"里子",不修的话,再漂亮的界面打开书仍然是网页质感。
