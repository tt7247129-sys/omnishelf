# 对照头部竞品的用户体验评估

> 方法:本应用**逐屏实测**(Android 13 模拟器,480×800,截图与耗时见下),
> 竞品依据公开版本的可用交互与官方更新说明。竞品无法在本机安装实测(需登录、有版权内容),
> 这部分标注为"公开行为",不与实测数据混用。

## 一、实测数据(本应用)

| 指标 | 实测值 | 说明 |
|---|---|---|
| 冷启动 | **1161 ms** | `am start -W`,低于 1500ms 的可接受线 |
| 热启动 | ~0 ms | 进程仍在时直接回前台 |
| 到"继续阅读"的步数 | **2 步** | 打开 → 点 Recent 列表里的书 |

| 库内书籍操作 | 10 项 | 长按卡片:打开/发送/删除/复制/移出/标签/播放列表/同步/重置进度/信息 |

## 三、最值得改的五处(按性价比排序)

### 1. 划线菜单:从"半屏面板"改成"悬浮条" — 影响最大

现在长按选词,弹出的是占半屏的面板:8 个色块 + 9 个动作 + 一个滚动列表。
头部产品的做法是**贴着选区浮一条工具条**(划线/想法/复制/搜索),色板和更多操作收进二级。

- 收益:阅读中断感显著下降;每次划线少一次滚动
- 成本:中(新布局 + 锚定定位 + 动画)
- 风险:低(不动选择引擎)

### 2. 听书要有自己的控制面板

TTS 现在只能从面板里的一个耳机图标进入,进去后是系统级弹层。
头部产品会在阅读页底部给一条**播放条**:播放/暂停、语速、定时、章节跳转。

- 收益:TTS 从"藏着的能力"变成"可见的功能",也是长时使用的核心场景
- 成本:中(新面板 + 绑定已有 TTSService)
- 风险:中(涉及前台服务,需回归通知与息屏)

### 3. 落地页加"继续阅读"卡片

现在落地是 Recent **列表**。头部的做法是一张横卡:封面 + 标题 + 进度 + 直接续读。

- 收益:打开即读的路径从 2 步降到 1 步,且第一屏有明确的视觉焦点
- 成本:中(上次因为书架的自定义布局挡过,需要走"列表内 header"或独立容器)
- 风险:中(此前两次尝试都栽在负边距布局上)

### 4. 设置页重排

现在是**一页长列表**(字体、颜色、翻页、TTS、库、同步全在一起),靠滚动找。

- 收益:找设置的耗时从"滚动搜索"变成"分类点击"
- 成本:中(分组标题 + 折叠)
- 风险:低(纯布局)

### 5. 无障碍补齐 109 处

- 收益:读屏用户可用;也是 Play 审核的加分项
- 成本:低但琐碎(每文件加 `contentDescription` 或标明装饰)
- 风险:极低

## 四、不建议做的

| 竞品做法 | 为什么不做 |
|---|---|
| 书籍推荐流 / 书城 | 需要版权与运营,与"本地阅读器"定位冲突 |
| 看他人想法 / 划线热力 | 需要账号与服务器,违背零收集承诺 |
| 阅读时长排行 / 社交 | 同上,且会把阅读变成竞赛 |
| 真人音色听书 | 版权与成本,系统 TTS 已覆盖主场景 |

## 五、结论

**能力层面,差距主要在"呈现"而不是"缺失"**:划线、笔记、TTS、标签、查找、词典全都有。
真正落后的是**这些能力的入口设计**——半屏面板、单页设置、无播放条、无继续阅读卡。

如果只做一件事:**把划线菜单改成悬浮条**。它每天被用几十次,是"这应用手感如何"的最直接来源。

如果做三件事:划线悬浮条 + 听书面板 + 设置分组。这三项都不碰阅读引擎,风险可控。
