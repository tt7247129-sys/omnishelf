Every software project reaches a moment when the code stops being the bottleneck. The
features work, the tests pass, the documents are written - and what remains is a list of
things that cannot be done from a terminal: hear the text-to-speech through an actual
speaker, look at a Chinese PDF with human eyes, get twelve testers to install the closed
build for two weeks, press the submit button on an account that belongs to someone else.

Calling that moment "done" feels like cheating, and calling it "not done" is also
cheating. Both are wrong in the same way: they treat the word as a fact about the code
when it is really a statement about who can do what remains.

## The ledger

The honest form of the word is a ledger. Every claim about the product sits in one table
with the measurement behind it: the tab order confirmed by a hierarchy dump, the
night-mode contrast measured at fourteen to one from raw pixels, the bundle identity
read back from the manifest, the memory curve after a reading session. Next to the
verified claims sits a shorter table of the unverifiable ones - the things a machine in
this room cannot confirm - and each row says exactly why.

A ledger is not the same as a checklist. A checklist asks whether a box can be ticked. A
ledger records what the tick was based on, so that when a claim turns out to be wrong,
the person reading it can see which measurement was bad instead of starting over.

## The reversal

The expected difficulty of finishing was technical - a hard bug, a missing library, a
performance cliff. The actual difficulty was resisting two easier endings. One says
"everything is verified" when half the evidence is inference. The other says "nothing
can be verified here" and leaves the work unfinished on principle. The ledger is the
path between them: verified where verification is possible, named where it is not, and
a handoff document that says plainly which of the remaining steps belong to a human.

## What this does not solve

A ledger does not make the remaining work smaller. The twelve testers still need to
install the build. The store still needs its video and its keystore. What the ledger
changes is only this: nobody has to re-derive what is known and what is not, and nobody
can quietly convert an assumption into a fact later.

## The product decision

Ship when the claims you make have evidence, and write down the claims you are not
making. That is the whole difference between a promise and a guess, and it is a product
decision like any other.
