# Contact

One address reaches the people who write the code. There is no ticket system and no first-line support script.

## Email

[hello@omnishelf.cc](mailto:hello@omnishelf.cc)

Use it for anything: a bug, a correction to an article, a licensing question, a request to remove something. Messages are read by the maintainers. Most get an answer within a few days; a difficult bug can take longer, and if it will, you will be told rather than left waiting.

## Bug reports

The public issue tracker is at [github.com/tt7247129-sys/omnishelf/issues](https://github.com/tt7247129-sys/omnishelf/issues). It is the fastest route for anything reproducible, because the report stays searchable for the next person who hits it.

A report that can be acted on contains four things:

        - The Android version and the device model.

        - The file format and, if possible, the file itself or a page from it.

        - What you did, in order, including whether the book came from local storage or a download.

        - What happened instead of what you expected.

A screenshot of a rendering problem is useful. A screenshot of a crash is not — the stack trace is, and it can be captured from a connected device with `adb logcat` if you are comfortable doing that.

## Privacy and data requests

The application collects no data, so there is nothing to export or delete. For anything relating to this website, including cookies and advertising systems, see the [privacy policy](/privacy/) and write to the address above.

## Security

If you believe you have found a security problem, write to the address above with "security" in the subject line rather than opening a public issue. You will get an acknowledgement, and the fix will be credited in the release notes unless you ask otherwise.
